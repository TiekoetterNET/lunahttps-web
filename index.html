Included Features

  • NGINX mainline as the base for current protocol and module support.
  • OpenSSL, following the latest stable release and pinned by version and SHA256, with TLS 1.3, kTLS, and ML-KEM-capable post-quantum TLS support.
  • Encrypted ClientHello (ECH) to hide the requested hostname in the TLS handshake, with a helper script for setup and key rotation.
  • HTTP/3 / QUIC alongside HTTP/1.1 and HTTP/2.
  • Brotli compression through ngx_brotli.
  • Real client IP handling behind trusted proxies through ngx_http_realip_module.
  • GeoIP2 support through ngx_http_geoip2_module.
  • Header manipulation through headers-more-nginx-module.
  • Response body substitution through ngx_http_substitutions_filter_module.

Container Usage

The image is published through GitHub Container Registry after CI succeeds on the main branch. 

docker pull ghcr.io/tiekoetter/lunahttps:latest

docker run --rm \
  -p 80:80/tcp \
  -p 443:443/tcp \
  -p 443:443/udp \
  ghcr.io/tiekoetter/lunahttps:latest

Published images carry a signed build provenance attestation, which can be checked with the GitHub CLI: 

gh attestation verify oci://ghcr.io/tiekoetter/lunahttps:latest --repo tiekoetter/lunahttps

Source Build

The public repository keeps the build process inspectable, repeatable, and CI-tested. 

git clone --recurse-submodules https://github.com/tiekoetter/lunahttps.git
cd lunahttps
sudo ./build.sh

Background

Luna-HTTP/S started in 2018 as a personal source-built NGINX setup. The goal was simple: build NGINX directly from source with the protocol, TLS, and module support needed for my own deployments. This public version keeps that long-running build reproducible and visible.
